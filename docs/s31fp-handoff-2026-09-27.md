## Clock — useful opportunity, NOT safe to ship yet

Real board CSR access works on both CPUs at approximately 320 MHz. CPU0
clock syscall ~2.7 us versus experimental MONOTONIC ~0.71 us / RAW ~0.48 us.
Short three-thread migration test: 2,378,880 experimental calls, no observed
backward values. This does not excuse source defects: owner-pid publication
race, plain-data seqlock races, fallback backward steps and delayed REALTIME
steps. S31CLK remains OFF. Clock test lifetime/data races were fixed too.

Review started on **existing generic kernel vDSO**, not a new custom clock
service. RISC-V's Kconfig and vdso Makefile restrict gettimeofday support to
64BIT; CSR reads and fallback syscall numbers need RV32/time64 handling.
No kernel source changes made. First review/build an isolated candidate using
existing Makefile routes; don't flash the rejected volume kernel or modify
musl/ld.so/libm. Do not ship the approximate clock merely because its short
board test passed.
