## 2026-09-20 morning: three dip levers built

User: "Why are we using X sockets at all?" - both ends are ours. Built:

1. **XLITE-RING** (xlite/xring.h, xlite/*.c, lvdesk/xshim.c): the X byte
   stream in a per-connection memfd (64 KB c2s + 32 KB s2c SPSC rings) with
   one O_NONBLOCK eventfd per direction as doorbell. Negotiated by
   QueryExtension("XLITE-RING") + Attach; the reply carries 3 fds on the
   socket; the socket then only carries SCM_RIGHTS (1-byte dummy; the ring
   reply says so with detail 0xFD) and its HUP. XConnectionNumber() returns
   the s2c eventfd so SDL's select() still works. XLITE_RING=0 /
   XSHIM_RING=0 turn it off. Doorbell rule: writer sets sig THEN writes the
   eventfd, and skips both if sig is already up; reader clears sig and
   drains the eventfd BEFORE looking at the ring. First boot: prboom's two
   connections attached and rendered at once.

## 2026-09-20 08:00-08:20 OpenTyrian audio: the synth is double-precision, this core has no D

User: "occasional clipped audio but never proper". Facts, all measured:
- Stream: 44100 Hz S16 stereo, period 512, buffer 8192, state XRUN, ~10
  underruns/s; each recover restarts from an empty buffer = clipped bursts.
  (alsa-lib's SNDERR prints garbage text for it on this libc - cosmetic.)
- CPU: 3% idle. Audio thread 56% of the core, game thread 18%.
- pcsample of the audio thread: ~50% in __muldf3 (libgcc soft double
  multiply) called from adlib_getsample (the OPL FM emulator, `double`
  throughout); our SDL->ALSA->s31route->I2S path appears only as the
  blocking ioctl wait (12% of wall, no CPU).
- rootfs/dblbench.c: double mul 705-723 ns, double add 420 ns, float mul
  24 ns, on this board. ~29x.
- Priority (S31ROUTE_NICE=-10, in our plugin, automatic): audio thread took
  92-100% of the core and still underran; game starved to 7%. Default OFF.
- rootfs/s31fp/: replacement __muldf3/__adddf3/__subdf3 (compiler-rt
  algorithms, RNE, no flags), bit-exact vs hardware IEEE over 20M random +
  edge operand pairs on the host. Board: mul 723 -> 296 ns (2.4x), add
  unchanged (402). OpenTyrian relinked with it (no source change): 102 ->
  78 underruns/10 s. With the boost too: thread at 100%, 130 underruns.
CONCLUSION: not fixable in the audio path - there is no CPU left to find
there. 44.1 kHz FM synthesis in software double does not fit this core.
What would work: upstream's own low-power profile (loudness.h:
OUTPUT_QUALITY 2 = 22 kHz under TARGET_GP2X/TARGET_DINGUX - a build define,
not a source edit) with s31fp, or music off. USER DECISION PENDING - they
consider config changes "cheating". s31fp is worth shipping platform-wide
regardless (every libm call is double); that is a toolchain/relink job.
